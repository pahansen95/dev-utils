The documentation in “ServiceManager.md” describes how the Service Manager orchestrates software services through the concept of system partitions and service sets. A system partition is an isolated environment—complete with its own namespaces—where a dedicated operator process runs as a fake-init to manage the lifecycle of service instances. Once started, the operator receives a fully assembled root filesystem containing extracted bundles for one or more services. It then spawns, monitors, and interacts with these service processes. Service sets define the configuration of multiple services, including processes, networking specifications, and dependencies, all packaged into a bundle. The operator applies these configurations within the partition, ensuring each service can run independently and be properly managed.
